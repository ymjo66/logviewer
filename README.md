# Log Viewer

ArduPilot DataFlash `.BIN` / `.log`를 PC 안에서 분석하는 로그 뷰어입니다. 단일 HTML과 주소창 없는 Windows x64 EXE를 제공합니다. 기본 브랜치는 `logviewer`입니다.

## 다운로드와 실행

| 파일 | 실행 환경 | 받기 |
| --- | --- | --- |
| LogViewer.html | Windows / Ubuntu 등, 최신 64비트 Chrome·Edge·Firefox·Chromium | [HTML 다운로드](https://github.com/ymjo66/logviewer/releases/latest/download/LogViewer.html) |
| LogViewer.exe | Windows 10/11 x64, .NET Framework 4.6.2 이상과 WebView2 Runtime | [EXE 다운로드](https://github.com/ymjo66/logviewer/releases/latest/download/LogViewer.exe) |
| 버전별 전체 파일 | HTML·EXE·체크섬·라이선스·개발 소스 | [릴리즈](https://github.com/ymjo66/logviewer/releases) |

HTML은 설치 과정 없이 내려받아 브라우저로 열면 됩니다. GitHub가 큰 HTML을 미리 표시하지 못하는 것은 다운로드 오류가 아닙니다. 저장소의 `index.html`에서 Download raw file을 눌러도 같은 파일을 받을 수 있습니다. 일반 실행에는 Node.js·Python·로컬 서버가 필요 없습니다.

EXE도 파일을 내려받아 실행하는 포터블 앱입니다. 별도 Windows 제목 표시줄 없이 프로그램 헤더에 창 이동·최소화·최대화·닫기를 통합합니다. 로고 기반 EXE 아이콘과 HTML 탭 아이콘을 사용합니다. HTML 파일 자체의 탐색기 아이콘은 운영체제의 기본 브라우저 연결을 따르며, 바로가기 등에 쓸 LogViewer.ico도 릴리즈에서 받을 수 있습니다. Microsoft Edge WebView2 Runtime이 없는 PC는 [Microsoft 공식 안내](https://developer.microsoft.com/microsoft-edge/webview2/)에 따라 별도 설치해야 합니다. 현재 EXE에는 코드 서명이 없습니다. 쓰기 가능한 사용자 폴더에 보관하면 업데이트를 적용하기 쉽습니다.

첫 화면에서 파일을 선택하거나 끌어다 놓으세요. 여러 로그를 추가할 수 있으며 왼쪽 목록에서 전환합니다. 예시 로그 자동 첨부 버튼은 제거했습니다. 개발 검증용 합성 로그는 `tests/fixtures/`에 따로 있습니다.

## 화면과 기능

### 차트 분석

상단 메뉴에서 차트 분석·비행 요약·센서 진단·이벤트 기록·파라미터 화면을 전환합니다. 왼쪽은 로그 목록과 필드 탐색기, 중앙은 분석 화면, 오른쪽은 공통 비행 경로·재생·자세 HUD입니다.

- 고도·스로틀, 진동·클리핑, 자세 추종, 측정 배터리 전압·전류, 모터 출력, GPS·자기장, EKF 프리셋을 제공합니다.
- 필드 탐색기는 로그의 FMT·FMTU·UNIT을 읽어 실제 기록된 메시지와 필드를 표시합니다. 검색·다중 선택이 가능하며 문자열과 정밀도 보존 정수는 목록에 표시하고 수치 차트 선택을 제한합니다.
- GPS[0], MAG[1], ORGN[0], STAK[10] 등의 센서 인스턴스를 구분합니다. 배열형 필드는 x[0] 등 원소별로 선택할 수 있습니다. 기록되지 않은 필드를 만들어 표시하지 않습니다.
- 사용자 지정 필드마다 독립된 세로축을 표시합니다. 축 제목·눈금은 곡선 색상을 따르고 축 범위 설정에서 시간·수치 범위를 지정할 수 있습니다.
- Chart.js 차트는 흰 배경과 곡선별 Min/Max/Mean 범례를 사용합니다. 범례를 클릭해 곡선을 숨기거나 표시합니다. 곡선 아래는 채우지 않습니다.
- 비행모드마다 연한 구간 배경과 차트 내부 모드명을 표시합니다. ALT_HOLD는 연한 노랑, LOITER는 연한 분홍 등 같은 모드는 같은 색상을 유지합니다.
- 메인 그래프 아래의 전체 구간 탐색 그래프에서 양끝 손잡이로 범위를 조절하거나 선택 영역을 이동합니다.

| 조작 | 동작 |
| --- | --- |
| 차트 왼쪽 드래그 | 선택 구간 확대 |
| 차트 오른쪽 드래그 | 시간축 좌우 이동 |
| 차트 휠 | 확대·축소 |
| 차트 더블클릭 | 전체 범위 복원 |
| 경로 왼쪽 드래그 | 화면 이동 |
| 경로 휠 | 확대·축소 |
| 3D 경로 휠 클릭 드래그 | 기울기·회전 |
| 원점이동 | 경로 보기 초기화 |

전체 보기에서도 시간축을 이동할 수 있으며 로그 바깥은 빈 공간으로 표시합니다. 확대할 때 원본 값으로 다시 계산합니다.

### 비행 요약과 진단

시동·이륙·착륙·시동 해제와 소티별 비행 시간을 표시합니다. ArduPilot 이벤트가 있으면 그 정보를 사용하고, 없으면 고도·스로틀 등으로 추정합니다. `비행 미감지`는 지상 기록이라는 단정이 아닙니다. 시각 선택에서 실제시각(KST)과 부팅경과(T+)를 구분하세요. 유효한 GPS 시각이 없으면 임의 날짜를 만들지 않고 T+로 표시합니다. 이착륙 판정은 사용자의 요청으로 직전 수정 이전 방식으로 복원했습니다.

진동·클리핑, GPS 위성·HDOP, 자세 추종, 모터 편차, 배터리 및 자기장 관련 진단을 정상·주의·경고로 표시합니다. 진단은 로그 검토를 돕는 지표이며 비행 안전을 보증하는 인증 판정이 아닙니다. 기준 설정에서 임계값과 배터리 셀 수를 조절합니다.

배터리는 셀별 전압 기록을 우선 사용하고 총전압만으로 셀 수를 구분하기 어려우면 미확정과 후보를 표시합니다. 임의로 셀 수를 단정하지 않습니다. 보드 전압과 무부하 추정전압은 배터리 차트에 표시하지 않습니다. 자기장 지표는 스로틀 연동 추정치이며 실측 CompassMot 간섭률과 다릅니다. [계산 설명](docs/magnetic-analysis.md)을 참고하세요.

### 경로·재생·내보내기

2D/3D GPS 경로, 이착륙 위치, 현재 재생 위치, 자세 HUD와 모터 출력을 표시합니다. 현재 3D는 오프라인 경로 뷰이며 위성 영상이나 지형 모델은 포함하지 않습니다.

왼쪽 CSV 저장에서 대상 로그와 데이터 열을 선택합니다. 비행 요약 또는 분석 타임라인을 내보냅니다. 차트 축·시각·재생 기능과 로그 추가 첨부, 이벤트·파라미터 확인 등 기존 기능은 유지합니다.

## 대용량 로그 처리

BIN은 8MiB씩 읽고 원본 바이트와 모든 패킷의 위치를 보관합니다. 행 객체 수백만 개를 미리 만드는 대신 선택한 값을 필요할 때 해석합니다. 텍스트 LOG도 전체 문자열을 split하지 않고 청크별로 해석하여 수치 열을 압축된 배열에 저장합니다. 분석 타임라인도 열 단위 저장소를 사용합니다. 요약본만 불러오거나 패킷·필드를 건너뛰는 방식이 아닙니다.

화면에 그리는 선은 픽셀 수에 맞춘 최소·최대 보존 표시를 사용하지만 원본 데이터는 그대로 남아 있습니다. 확대 시 원본을 다시 조회하고 통계는 해당 데이터 전체에서 계산합니다.

800MB 이상 합성 BIN의 전체 패킷 수와 경계·배열·64비트 값 보존을 검증했습니다. 기존 실제 BIN의 전체 데이터 필드와 분석 타임라인도 이전 파서와 비교합니다. 테스트 방법은 아래를 참고하세요. 파일 전체 원본은 메모리에 남으므로 메모리 사용량이 파일 크기와 무관해지는 것은 아닙니다. 로그 구성·PC 메모리에 따라 한계가 있으며 모든 800MB 파일의 처리 성공을 보장하지 않습니다. 고밀도 필드 계산 중 일시적인 화면 정지가 있을 수 있습니다. [구조와 한계](docs/large-logs.md).

현재 EXE는 WebView2에서 같은 분석 코드를 실행합니다. EXE 자체가 브라우저의 메모리 제한을 없애지는 않습니다. 서버에 로그를 올릴 필요는 없습니다.

## 개인정보와 네트워크

파일 읽기·분석·CSV 생성은 PC 안에서 처리하며 사용자 로그를 서버로 전송하지 않습니다. HTML에는 라이브러리·폰트·로고가 포함되어 있어 오프라인으로 분석할 수 있습니다. 외부 문서 링크는 사용자가 열 때 연결됩니다. EXE는 실행 시 GitHub 릴리즈에 업데이트 확인 요청을 보내고 새 버전이 있으면 공개 배포 파일을 내려받습니다. 로그 내용은 이 요청에 포함하지 않습니다.

## EXE 자동 업데이트

1. 실행 시 `ymjo66/logviewer`의 최신 정식 GitHub Release를 확인합니다. 별도 확인 버튼이나 상태 표시줄은 표시하지 않습니다.
2. 현재 버전보다 높은 정식 버전이 있으면 `LogViewer.exe`와 `SHA256SUMS.txt`를 자동 다운로드하고 해시를 검증합니다.
3. 작업 중인 로그를 중단하지 않고 프로그램을 정상 종료할 때 파일을 교체합니다. 다음에 실행하면 새 버전이 열립니다. 업데이트 때문에 프로그램을 자동으로 다시 열거나 확인 창을 표시하지 않습니다.
4. 인터넷이 없어도 분석은 계속할 수 있습니다. 쓰기 권한이 없는 설치 경로는 교체에 실패할 수 있습니다. 교체 전 파일은 `.bak`으로 남깁니다.

HTML 파일은 자동 교체하지 않습니다. 새 버전 HTML을 다시 내려받으세요. 업데이트 게시자는 저장소의 릴리즈 권한을 신뢰합니다. SHA256은 다운로드 파일과 릴리즈 체크섬의 일치를 확인하며 별도 전자서명을 대신하지 않습니다.

## 개발 환경과 소스 구조

Node.js 20 이상과 npm이 개발 빌드에 필요합니다. 권장 환경은 Node.js LTS입니다. Windows·Ubuntu 모두 HTML 개발이 가능하며 Windows EXE는 Windows에서 빌드합니다.

```sh
npm ci
npm run dev
```

`http://127.0.0.1:8767/`을 열고 `src/` 파일을 수정하세요. 저장하면 HTML을 다시 빌드합니다. 브라우저를 직접 새로고침하면 변경이 적용되며 첨부 로그는 초기화됩니다. 배포 HTML은 생성 결과이므로 지속적인 수정은 `src/`에서 하세요.

| 위치 | 내용 |
| --- | --- |
| src/index.template.html | 화면 구조와 파일 결합 순서 |
| src/styles/ | 화면·차트·레이아웃·내장 폰트 스타일 |
| src/js/parser.js | 기준 DataFlash 해석 및 검색 |
| src/js/large-parser.js | 청크 읽기·모든 패킷 색인·원본 값 해석 |
| src/js/storage.js | 원본 행과 분석 타임라인의 메모리 절감 저장소 |
| src/js/analysis.js | 비행·진단·시각·자기장 계산 |
| src/js/charts.js | Chart.js·축·필드·모드·탐색 그래프 |
| src/js/route.js | 2D/3D 경로·HUD·재생 |
| src/js/ui.js / workbench.js | 로그 관리·탐색기·UI 조작 |
| src/js/battery.js / csv.js | 셀 수 판정·선택 항목 CSV |
| src/vendor/chart.js | 배포에 내장되는 라이브러리 |
| desktop/Program.cs | 주소창 없는 Windows 앱·업데이트 |
| scripts/ | HTML·EXE 빌드와 배포 준비 |
| tests/ | 회귀 검증 및 합성 데이터 |
| licenses/ | 제3자 라이선스 원문 |

```sh
npm test
npm run build
npm run build:exe
```

`npm run build`는 `index.html`과 `dist/LogViewer.html`을 만듭니다. `build:exe`는 Windows의 .NET Framework C# 컴파일러와 공식 WebView2 SDK를 사용해 `dist/LogViewer.exe`와 체크섬을 만듭니다. SDK는 첫 빌드 시 공식 NuGet에서 고정 버전으로 내려받습니다. PowerShell 실행 정책 변경은 필요 없습니다.

대용량 검증(약 845MB 합성 파일이 artifacts에 생성됨):

```sh
node --max-old-space-size=256 tests/large-parser.cjs --stress --plot
node tests/large-parser.cjs --real /path/to/flight.BIN
```

첫 명령은 전체 패킷 보존과 사용자 지정 필드 통계를 확인합니다. 두 번째 명령은 실제 로그의 모든 필드·타임라인·진단을 기존 파서와 비교합니다. 실제 비행 로그는 저장소나 릴리즈에 포함하지 않습니다. `artifacts/`, `dist/`, `node_modules/`는 Git에서 제외합니다.

## 릴리즈 관리

버전을 `package.json`과 잠금 파일에서 올리고 변경 내용을 검증한 뒤 커밋합니다. `v1.0.2`와 같은 태그를 게시하면 Windows 빌드 워크플로가 HTML·EXE·체크섬·고지·대응 소스를 정식 릴리즈로 게시합니다. 앱 업데이트가 작동하려면 EXE와 SHA256SUMS 파일명을 유지해야 합니다. 프리릴리즈와 낮거나 같은 버전은 자동 적용하지 않습니다.
