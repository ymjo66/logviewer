# Log Viewer

ArduPilot DataFlash `.BIN` / `.log`를 PC 안에서 분석하는 로그 뷰어입니다. 단일 HTML과 주소창 없는 Windows x64 EXE를 제공합니다. 기본 브랜치는 `logviewer`입니다.

## 다운로드와 실행

| 파일 | 실행 환경 | 받기 |
| --- | --- | --- |
| LogViewer.html | Windows / Ubuntu 등, 최신 64비트 Chrome·Edge·Firefox·Chromium | [HTML 다운로드](https://github.com/ymjo66/logviewer/releases/latest/download/LogViewer.html) |
| LogViewer.exe | Windows 10/11 x64, .NET Framework 4.6.2 이상과 WebView2 Runtime | [EXE 다운로드](https://github.com/ymjo66/logviewer/releases/latest/download/LogViewer.exe) |
| 버전별 전체 파일 | HTML·EXE·체크섬·라이선스·개발 소스 | [릴리즈](https://github.com/ymjo66/logviewer/releases) |

HTML은 설치 과정 없이 내려받아 브라우저로 열면 됩니다. GitHub가 큰 HTML을 미리 표시하지 못하는 것은 다운로드 오류가 아닙니다. 저장소의 `index.html`에서 Download raw file을 눌러도 같은 파일을 받을 수 있습니다. 일반 실행에는 Node.js·Python·로컬 서버가 필요 없습니다.

EXE도 파일을 내려받아 실행하는 포터블 앱입니다. 별도 Windows 제목 표시줄 없이 프로그램 헤더에 창 이동·최소화·최대화·닫기를 통합합니다. 로고 기반 EXE 아이콘과 HTML 탭 아이콘을 사용합니다. HTML 파일 자체의 탐색기 아이콘은 운영체제의 기본 브라우저 연결을 따르며, 바로가기 등에 쓸 LogViewer.ico도 릴리즈에서 받을 수 있습니다. Microsoft Edge WebView2 Runtime이 없는 PC는 [Microsoft 공식 안내](https://developer.microsoft.com/microsoft-edge/webview2/)에 따라 별도 설치해야 합니다. 현재 EXE에는 코드 서명이 없습니다. 쓰기 가능한 사용자 폴더에 보관하면 업데이트를 적용하기 쉽습니다.

첫 화면에서 파일을 선택하거나 끌어다 놓으세요. 첨부 시에는 전체 원본 인덱스와 비행횟수·기록 종료 의심 여부만 계산합니다. 처음에는 상세 분석을 자동으로 시작하지 않으며, 왼쪽에서 로그를 선택하면 해당 로그의 비행요약·통계·센서 진단을 계산합니다. 목록은 미분석·분석 중·완료·실패 상태를 표시하고 정상·주의 배지는 센서 진단에서 확인합니다. 여러 로그를 추가할 수 있으며 왼쪽 목록에서 전환합니다. 예시 로그 자동 첨부 버튼은 제거했습니다. 개발 검증용 합성 로그는 `tests/fixtures/`에 따로 있습니다.

## 화면과 기능

### 차트 분석

상단 메뉴에서 차트 분석·비행 요약·센서 진단·이벤트 기록·파라미터 화면을 전환합니다. 왼쪽은 로그 목록과 필드 탐색기, 중앙은 분석 화면, 오른쪽은 공통 비행 경로·재생·자세 HUD입니다.

- 빠른 프리셋은 진동·클리핑, 자세 추종, 모터 출력, EKF 네 가지만 표시합니다. 다른 항목은 전체 필드 탐색기로 선택할 수 있습니다.
- 모터 출력 차트는 `SERVOx_FUNCTION`의 Motor1~12 매핑을 우선 읽어 실제 RCOU 채널을 표시합니다. 매핑이 없고 기체 형식을 알면 쿼드·헥사·옥타 등의 기본 출력 순서를 추정했다고 표시합니다. 형식/매핑을 확인할 수 없으면 기록된 채널을 출력 채널로 표시하며 모터 수를 단정하지 않습니다. [ArduPilot 출력 매핑](https://ardupilot.org/copter/docs/common-rcoutput-mapping.html)을 따릅니다.
- 필드 탐색기는 로그의 FMT·FMTU·UNIT을 읽어 실제 기록된 메시지와 필드를 표시합니다. 검색·다중 선택이 가능하며 문자열과 정밀도 보존 정수는 목록에 표시하고 수치 차트 선택을 제한합니다.
- GPS[0], MAG[1], ORGN[0], STAK[10] 등의 센서 인스턴스를 구분합니다. 배열형 필드는 x[0] 등 원소별로 선택할 수 있습니다. 기록되지 않은 필드를 만들어 표시하지 않습니다.
- 사용자 지정 필드마다 독립된 세로축을 표시합니다. 축 제목·눈금은 곡선 색상을 따르고 축 범위 설정에서 시간·수치 범위를 지정할 수 있습니다.
- 같은 계열의 필드는 축을 각각 표시하되 자동 범위는 통일합니다. 예를 들어 RCOU.C1~C8은 공통 범위를 사용하고 GPS 고도·속도는 각각 다른 범위를 사용합니다. 벡터 성분·배열 원소·같은 필드의 센서 인스턴스에도 적용하며, 직접 입력한 축 범위가 우선합니다. 기본 프리셋과 비교 그래프에서도 곡선·축 제목·눈금·축선의 색상을 일치시킵니다.
- Chart.js 차트는 흰 배경과 곡선별 Min/Max/Mean 범례를 사용합니다. 범례를 클릭해 곡선을 숨기거나 표시합니다. 곡선 아래는 채우지 않습니다.
- 비행모드마다 연한 구간 배경과 차트 내부 모드명을 표시합니다. ALT_HOLD는 연한 노랑, LOITER는 연한 분홍 등 같은 모드는 같은 색상을 유지합니다.
- 메인 그래프 아래의 전체 구간 탐색 그래프에서 양끝 손잡이로 범위를 조절하거나 선택 영역을 이동합니다.
- 차트 분석 하단의 **다중 로그 비교**에서 로그와 항목(고도·속도·전압·전류·진동·자세·모터·GPS·자기장)을 체크해 여러 항목을 한 그래프에 표시합니다. 같은 항목은 로그 간 공통 범위의 색상 축을 사용하고 다른 항목은 별도 범위를 사용합니다. 로그는 색상, 항목은 선 모양으로 구분하며 범례에 둘 다 표시합니다. 각 로그 시작 또는 첫 이륙을 0초로 정렬합니다. 비교는 분석 타임라인을 사용하며 원본 BIN 캐시를 추가로 불러오지 않습니다. 해당 필드가 없거나 이륙 기준을 정할 수 없는 로그는 이유와 함께 제외합니다. 비교 그래프의 휠 확대·오른쪽 드래그 이동·전체 범위 복원은 메인 차트와 독립적입니다.
- 상단에 대용량 사용 안내와 첨부 원본 합계 용량을 표시합니다. 현재 버전의 안정적인 최대 GB·파일 개수는 검증되지 않았으며, 실제 대용량 다중 첨부에서는 메모리 할당 및 읽기 실패가 보고되었습니다. 예시 파일의 개수 테스트를 실제 대용량 처리 보장으로 해석하면 안 됩니다.
- 비교 그래프의 **전체 원본 필드 선택**에서 첨부 로그의 전체 필드를 검색하고 여러 개 선택할 수 있습니다. GPS[0] 같은 센서 인스턴스와 배열 원소도 구분합니다. 숫자로 표현할 수 없는 문자열·정밀도 보존 정수는 목록에 표시하되 차트 선택은 제한합니다. 기록이 없는 로그는 제외 이유를 표시합니다. 원본 필드 비교는 원본의 TimeUS와 값을 사용하며 기본 분석 항목과 함께 선택할 수 있습니다. HTML은 로그별 원본을 순차 조회하고, EXE는 디스크 엔진에서 조회합니다.

| 조작 | 동작 |
| --- | --- |
| 차트 왼쪽 드래그 | 선택 구간 확대 |
| 차트 오른쪽 드래그 | 시간축 좌우 이동 |
| 차트 휠 | 확대·축소 |
| 차트 더블클릭 | 전체 범위 복원 |
| 경로 왼쪽 드래그 | 화면 이동 |
| 경로 휠 | 확대·축소 |
| 3D 경로 휠 클릭 드래그 | 기울기·회전 |
| 원점이동 | 경로 보기 초기화 |

전체 보기에서도 시간축을 이동할 수 있으며 로그 바깥은 빈 공간으로 표시합니다. 확대할 때 원본 값으로 다시 계산합니다.

차트 드래그 중에는 현재 표시 데이터를 사용하고 시간축만 이동합니다. 손을 놓으면 최종 구간을 갱신하며, 휠은 마지막 입력 후 약 160ms 뒤 갱신합니다. 미리보기 중에는 이전 통계가 남을 수 있으므로 조회 상태를 함께 표시합니다. EXE는 원본 조회·통계·축 계산을 별도 Worker에서 실행하고 새 조작이 들어오면 이전 Worker와 네이티브 필드 조회를 취소합니다. 늦게 도착한 이전 결과는 적용하지 않습니다. 전체 구간 탐색 그래프는 로그·필드가 바뀌지 않으면 재사용합니다. HTML도 조작 중 반복 계산을 생략하지만 최종 계산은 브라우저의 기존 방식입니다.

### 비행 요약과 진단

시동·이륙·착륙·시동 해제와 소티별 비행 시간을 표시합니다. ArduPilot 이벤트가 있으면 그 정보를 사용하고, 없으면 고도·스로틀 등으로 추정합니다. `비행 미감지`는 지상 기록이라는 단정이 아닙니다. 시각 선택에서 실제시각(KST)과 부팅경과(T+)를 구분하세요. 유효한 GPS 시각이 없으면 임의 날짜를 만들지 않고 T+로 표시합니다. 이착륙 판정은 사용자의 요청으로 직전 수정 이전 방식으로 복원했습니다.

진동·클리핑, GPS 위성·HDOP, 자세 추종, 모터 편차, 배터리 및 자기장 관련 진단을 정상·주의·경고로 표시합니다. 진단은 로그 검토를 돕는 지표이며 비행 안전을 보증하는 인증 판정이 아닙니다. 기준 설정에서 임계값과 배터리 셀 수를 조절합니다.

배터리는 셀별 전압 기록을 우선 사용하고 총전압만으로 셀 수를 구분하기 어려우면 미확정과 후보를 표시합니다. 임의로 셀 수를 단정하지 않습니다. 보드 전압과 무부하 추정전압은 배터리 차트에 표시하지 않습니다. 자기장 지표는 스로틀 연동 추정치이며 실측 CompassMot 간섭률과 다릅니다. [계산 설명](docs/magnetic-analysis.md)을 참고하세요.

### 경로·재생·내보내기

2D/3D GPS 경로, 이착륙 위치, 현재 재생 위치, 자세 HUD와 모터 출력을 표시합니다. 현재 3D는 오프라인 경로 뷰이며 위성 영상이나 지형 모델은 포함하지 않습니다.

왼쪽 CSV 저장에서 대상 로그와 데이터 열을 선택합니다. 미분석 로그도 선택할 수 있으며 필요한 상세 분석을 순서대로 완료한 뒤 내보냅니다. 분석 실패 시 완성된 CSV로 저장하지 않고 오류를 표시합니다. 비행일지 일괄 복사와 로그 비교도 필요한 분석을 먼저 완료합니다. 비행 요약 또는 분석 타임라인을 내보냅니다. 차트 축·시각·재생 기능과 로그 추가 첨부, 이벤트·파라미터 확인 등 기존 기능은 유지합니다.

## 대용량 로그 처리

**1.0.3 EXE는 C# 네이티브 파서와 디스크 저장소를 사용합니다.** 원본은 복사 없이 읽기 전용으로 직접 조회하고, 모든 패킷의 위치·스키마·시간 인덱스와 분석 타임라인만 로컬 디스크에 저장합니다. BIN은 4MiB씩 스캔하고 필드는 8MiB 메모리 매핑 창에서 필요할 때 해석합니다. 텍스트 LOG도 청크로 읽고 원본을 직접 읽고 행 인덱스를 디스크에 보관합니다. 요약본만 불러오거나 원본 패킷·필드를 제거하지 않습니다.

기존 비행·센서 진단 규칙은 백그라운드 Worker에서 재사용합니다. 분석 타임라인을 만드는 중에도 페이지를 디스크에 기록하며, 화면은 필요한 페이지를 조회합니다. 주 화면과 Worker 각각의 페이지 캐시는 추정 크기 16MiB를 상한으로 교체합니다. 이 수치는 앱 전체 메모리 상한이 아닙니다. WebView2·차트·진단 작업용 데이터와 런타임은 추가 메모리를 사용합니다. 재분석은 새 결과 저장이 끝난 후 전환하며 실패하면 이전 결과를 유지합니다. CSV도 큰 문자열 하나를 만들지 않고 나누어 저장합니다.

캐시는 `%LOCALAPPDATA%/LogViewer/disk-cache/<실행별 ID>/`에 생성됩니다. 원본 복사 공간은 필요하지 않으며 패킷당 24바이트 인덱스와 분석 결과·재분석 중간 파일을 위한 디스크 여유 공간이 필요합니다. 원본은 로그가 첨부된 동안 읽기 전용 핸들로 보호합니다. 목록에서 제거하거나 종료하기 전에는 원본을 수정·이동하거나 저장 장치를 분리하지 마세요. 해당 로그를 목록에서 제거하거나 창을 정상 종료하면 그 캐시를 지웁니다. 강제 종료·전원 중단 때는 임시 파일이 남을 수 있습니다. 모든 Log Viewer 창을 닫은 뒤 남은 `disk-cache` 폴더를 정리할 수 있으며 사용자가 첨부한 원본 파일은 삭제하지 않습니다.

차트 선은 화면 크기에 맞춘 최소·최대 피크 보존 표시를 사용합니다. 원본은 남아 있으며 확대하면 다시 조회하고 Min/Max/Mean은 조회 범위의 전체 수치에서 계산합니다. 이 표시 최적화와 원본을 요약해서 불러오는 것은 다릅니다.

**단일 HTML에는 네이티브 엔진이 없습니다.** 기존 8MiB 청크 파서·비활성 BIN 원본 캐시 해제를 사용하며 인덱스와 분석 결과는 메모리에 남습니다. 브라우저 방식의 대용량 한계가 그대로 있으므로 많은 큰 로그에는 EXE를 사용하세요. 두 방식 모두 서버 업로드나 GPU 연산을 요구하지 않습니다. 검증 범위와 남은 한계는 [대용량 처리 문서](docs/large-logs.md)를 참고하세요.

## 개인정보와 네트워크

파일 읽기·분석·CSV 생성은 PC 안에서 처리하며 사용자 로그를 서버로 전송하지 않습니다. HTML에는 라이브러리·폰트·로고가 포함되어 있어 오프라인으로 분석할 수 있습니다. 외부 문서 링크는 사용자가 열 때 연결됩니다. EXE는 실행 시 GitHub 릴리즈에 업데이트 확인 요청을 보내고 새 버전이 있으면 공개 배포 파일을 내려받습니다. 로그 내용은 이 요청에 포함하지 않습니다.

## EXE 자동 업데이트

1. 실행 시 `ymjo66/logviewer`의 최신 정식 GitHub Release를 확인합니다. 요청 시간 제한과 재시도를 적용하고 API가 실패하면 GitHub 릴리즈 웹 주소로 대체 조회합니다. 별도 확인 창·상태 표시줄은 표시하지 않습니다.
2. 높은 정식 버전 또는 같은 버전의 다른 배포 파일(SHA256 기준)이 있으면 `LogViewer.exe`와 `SHA256SUMS.txt`를 내려받고 검증합니다. 동일한 파일은 중복 갱신하지 않으며 낮은 버전으로 자동 변경하지 않습니다.
3. 작업 중인 로그를 중단하지 않고 프로그램을 정상 종료할 때 파일을 교체합니다. 다음에 실행하면 새 버전이 열립니다. 업데이트 때문에 프로그램을 자동으로 다시 열거나 확인 창을 표시하지 않습니다.
4. 실행 중 10분 간격으로 다시 확인합니다. 상태는 기존 **라이선스 · 소스코드** 창에서 볼 수 있으며 진단 기록은 `%LOCALAPPDATA%/LogViewer/update.log`에 남습니다. 인터넷이 없어도 분석은 계속할 수 있습니다. 쓰기 권한이 없는 설치 경로는 교체에 실패할 수 있습니다. 임시 파일 검증 후 원자적으로 교체하며 이전 파일은 `.bak`으로 남깁니다.

HTML 파일은 자동 교체하지 않습니다. 새 버전 HTML을 다시 내려받으세요. 업데이트 게시자는 저장소의 릴리즈 권한을 신뢰합니다. SHA256은 다운로드 파일과 릴리즈 체크섬의 일치를 확인하며 별도 전자서명을 대신하지 않습니다.

## 개발 환경과 소스 구조

Node.js 20 이상과 npm이 개발 빌드에 필요합니다. 권장 환경은 Node.js LTS입니다. Windows·Ubuntu 모두 HTML 개발이 가능하며 Windows EXE는 Windows에서 빌드합니다.

```sh
npm ci
npm run dev
```

`http://127.0.0.1:8767/`을 열고 `src/` 파일을 수정하세요. 저장하면 HTML을 다시 빌드합니다. 브라우저를 직접 새로고침하면 변경이 적용되며 첨부 로그는 초기화됩니다. 배포 HTML은 생성 결과이므로 지속적인 수정은 `src/`에서 하세요.

```sh
npm test
npm run build
npm run build:exe
```

`npm run build`는 `index.html`과 `dist/LogViewer.html`을 만듭니다. `build:exe`는 Windows의 .NET Framework C# 컴파일러와 공식 WebView2 SDK를 사용해 `dist/LogViewer.exe`와 체크섬을 만듭니다. SDK는 첫 빌드 시 공식 NuGet에서 고정 버전으로 내려받습니다. PowerShell 실행 정책 변경은 필요 없습니다.

대용량 검증(약 845MB 합성 파일이 artifacts에 생성됨):

```sh
node --max-old-space-size=256 tests/large-parser.cjs --stress --plot
node tests/large-parser.cjs --real /path/to/flight.BIN
node tests/native-disk.cjs
node tests/native-disk.cjs /path/to/flight.BIN
```

첫 명령은 전체 패킷 보존과 사용자 지정 필드 통계를 확인합니다. 두 번째 명령은 실제 로그의 모든 필드·타임라인·진단을 기존 파서와 비교합니다. 실제 비행 로그는 저장소나 릴리즈에 포함하지 않습니다. `artifacts/`, `dist/`, `node_modules/`는 Git에서 제외합니다.

같은 종류와 범위를 사용하는 세로축은 하나만 표시하고 중복 축은 숨깁니다. 범례는 테두리 박스 안에서 세로로 배치하고 필드 이름과 최소·최대·평균을 유지합니다. 긴 항목은 화면 폭에 맞춰 줄바꿈합니다. 서로 다른 종류나 수동 범위는 독립 축을 유지합니다. 구간 조회 상태는 차트 위에 겹쳐 표시하여 확대·축소 중 차트 높이가 바뀌지 않습니다.

상세 분석 결과는 최근 3개 로그까지 화면 캐시에 유지하며 CSV가 읽는 결과는 작업이 끝날 때까지 보호합니다. EXE의 완료된 결과는 세션 디스크 저장소에서 다시 사용할 수 있습니다. 설정이 바뀌면 이전 상세 결과를 재사용하지 않습니다. 로그 선택이 바뀌면 EXE 분석 Worker를 취소하고 이전 선택의 결과가 화면에 반영되지 않도록 확인합니다. 원본 패킷과 필드는 생략하지 않으며, 초기 첨부에도 인덱스 생성 및 이착륙 판정에 필요한 순회 시간이 듭니다.

EXE 분석은 센서 선택·정렬처럼 순차적으로 읽는 단계에서 원본을 512행씩 조회하고, 여러 센서를 번갈아 읽는 타임라인 단계에서는 128행씩 조회합니다. 캐시 상한은 유지하며 분석 결과 저장이 변경되지 않은 원본 캐시를 비우지 않도록 분리했습니다. 원본 패킷·필드와 분석 규칙은 유지합니다.

로딩 단계별 시간 측정이 필요하면 Windows EXE를 다음처럼 실행한 뒤 로그를 첨부합니다. 지정한 JSON 파일에 인덱스 생성, 분석 단계, 필드 목록, 결과 저장 및 페이지 요청 시간이 기록됩니다. 일반 실행에서는 측정 파일을 저장하지 않습니다. 최초 차트 렌더링 시간은 포함하지 않으며, RPC 시간은 분석 시간에 포함되므로 별도로 더하지 않습니다.

```powershell
.\LogViewer.exe --profile-output "C:\Temp\load-profile.json"
```

## 릴리즈 관리

버전을 `package.json`과 잠금 파일에서 올리고 변경 내용을 검증한 뒤 커밋합니다. `v1.0.2`와 같은 태그를 게시하면 Windows 빌드 워크플로가 HTML·EXE·체크섬·고지·대응 소스를 정식 릴리즈로 게시합니다. 앱 업데이트가 작동하려면 EXE와 SHA256SUMS 파일명을 유지해야 합니다. 프리릴리즈와 낮은 버전은 자동 적용하지 않습니다. 같은 버전은 배포 EXE 업로드 시각이 현재 빌드보다 최신이고 SHA256이 달라졌을 때만 갱신합니다. 업로드 시각이 없는 대체 조회에서는 같은 버전을 덮어쓰지 않습니다. 구형 EXE에서 자동 업데이트가 동작하지 않으면 최신 릴리즈의 EXE를 직접 다운로드해 교체하세요.
